# iPad 定位圖 AR 使用與驗收

此模式使用後置鏡頭和紙上定位圖追蹤同一平面，保留網頁使用方式。現有 Wonderland 空間 AR 入口仍可供相容 Android 裝置使用。定位圖模式不需要 immersive-ar WebXR；能否穩定使用仍須在目標 iPad 和瀏覽器實測。

## 操作

1. 在網站的「AR → 開啟／列印定位圖」列印 VisionLink ID 17。保留正方形、黑框和完整白邊，勿鏡像列印。
2. 將定位圖固定在要檢查的設備面板、桌面或貨箱表面。**定位圖和要畫的目標必須在同一平面**，相距不超過約兩個圖寬；現場僅放一張這個定位圖。
3. 發起方建立房間並開啟後置鏡頭，選「AR → 定位圖 AR」。鏡頭須持續看見整張定位圖，等待「定位圖已鎖定」。定位期間暫停 AI 分析，離開 AR 後恢復原本設定。
4. 受邀方打開完整邀請連結，加入房間，切換「夥伴視角」。按「擷取現場參考圖」，選箭頭／圈選／畫線／文字，輸入或選常用指令，在相機畫面內繪圖，避開兩側留白。
5. 受邀方按「固定到實物（AR）」。發起方查看綠色预覽是否落在正確表面，再按「確認固定」。確認後轉為黃色；發起方只確認位置，不能改寫受邀方的圖或文字。
6. 受邀方按「返回即時畫面」。移動 iPad 查看標記是否跟隨目標平面，並確認遠端影像仍持續更新。

參考圖有效兩分鐘。更換目標、搬動定位圖或設備後，離開 AR 重新進入，再取圖和畫指令。失去定位圖時標記會隱藏；恢復穩定追蹤後再顯示。只顯示最新指令，避免累積遮擋；受邀方可撤銷或清除。

## 方向與定位

後置鏡頭畫面不做鏡像。辨識器傳回依印刷圖案方向排序的四個角，不能按畫面左上重新排序。參考圖與角點取自同一幀，遠端 2D 點先扣掉留白，再映射到紙面座標，最後依當下四角重新投影。箭頭、圈選和畫線保留原本路徑；文字錨點跟隨平面，但字形始終面向閱讀者。

鏡頭傾斜時，平面上的圓自然看起來像橢圓；這是透視，與左右顛倒不同。此模式不推算定位圖以外物件的深度，不能用桌面上的圖定位到更高的按鈕或垂直面板。

Wonderland 空間 AR 同樣改為以參考圖的實際相機姿態投射至現場選擇的表面；取消原本固定 25 公分重畫的流程。參考圖過期、AR 重啟或工作區重設後須重新擷取。

## 已驗證與待驗證

- 自動測試：實際 js-aruco2 辨識器的四個旋轉方向、透視、鏡像圖拒絕；直橫向留白轉換；箭頭／圓／線／文字投影；過期與失去追蹤；角色權限。
- 桌面 Edge 的雙人測試：真實 WebRTC、合成後置鏡頭、正式工作空間按鈕、三種指令確認、旋轉、相機寬高交換、失去定位圖與恢復、離開 AR 恢復普通鏡頭。產物保存在 `artifacts/marker-ar-qa/`。
- **尚未完成第 9 代 iPad、iPadOS 27.0 Chrome 的實機驗收。** 實機應各用直式／橫式操作，連續共享至少五分鐘，確認文字可讀、箭頭指向一致，遮住定位圖後標記消失、重現後恢復。

## 開發與授權

定位圖辨識器取自 [js-aruco2](https://github.com/damianofalcioni/js-aruco2/tree/0491d5d228746411d0e9dd602b98f48636a644ba)，固定版本並隨站提供，保留 `vendor/aruco/LICENSE.txt`。無第三方 CDN 即時依賴。

執行 `node scripts/build-marker-runtime.mjs` 重建 ESM 入口及 SVG；`npm run check` 執行邏輯回歸。已安裝 Playwright 時執行 `node scripts/marker-ar-smoke.mjs`，或以 `PLAYWRIGHT_MODULE` 指向該套件的 `index.mjs`。
